How this sheet works

The sell-side script produces a story and one confident number. This sheet produces typed variables. The build consumes per-workflow inputs, never an aggregate, so each question below is annotated with the symbol it produces, its unit, its constraint, and its source class. A captured field is only useful to the build if it carries a class.

D
D  discovery-locked → becomes a build variable
B
B  build-set → engineer fixes after the call
L
L  logs → fills from live data post go-live
C
C  client-owned → never measured by us
Computed output 1 · Hours back  (client-facing)
Hours_back = sum_w [ ( V_success_w · M_w · C_w ) − ( V_flagged_w · M_flag_w ) ] / 60
Discovery owns exactly one symbol: M_w, the owner’s minutes per task instance, per workflow, held ~20% conservative and locked on a per-task yes. V_success_w / V_flagged_w come from logs (L); C_w completeness and M_flag_w are build-set (B). Run per workflow, never as a lump: a negative per-workflow term is the signal that a workflow is not yet earning its oversight.
Computed output 2 · Price
Rev_m = u_val × u_pm   |   Tier = max( tier(Rev_m), tier(headcount) )
SetupFee = fixed(Tier)   |   Retainer = PartA(scope) + PartB(band(u_pm)) + PartC( 0.02 × Rev_m, cap £40k ) ; floor £2,500
Every input here is a discovery-locked field: u_val, u_pm → Rev_m (Q11), headcount (setter brief), scope = the three confirmed pains (Q2 + reflect). Tier takes whichever signal points higher.

Computed on the call · price

Q11 gives revenue, which confirms or lifts the setter’s headcount tier. Place by whichever signal points higher. Setup is fixed to the tier; the retainer is the flexible piece, seated as the three-number anchor and made exact for the demo. Internal — never shown to the prospect.

Retainer · three-number anchor (rough on call, exact at demo)
Retainer = PartA(scope) + PartB(band(u_pm)) + PartC( 0.02 × Rev_m, cap £40k/mo ) ; absolute floor £2,500
Part A is scope-based (£2k–£7k). Part B is the volume/profile surcharge band off u_pm. Part C is 2% of gross monthly revenue, capped £40k/mo. The axis you voice is scope (high / middle / low), not volume.

Invariants

  • Capture m_w and v_w per task, never a lump. You cannot recover per-workflow M_w from an aggregate, and per-workflow is mandatory — it is what lets the Ops auditor flag a workflow not earning its oversight.
  • One symbol is discovery’s on Hours back: M_w. The V counts, completeness C, and M_flag are not yours to capture.
  • Named, not categorical. Channels and system are product names (chan[ ], sys), or the tile builds generic.
  • Shape now, harden in build. The ruleset Θ leaves the call at shape-fidelity; fields and thresholds are hardened in the three-day window. Make that handoff explicit.
  • Never capture a baseline you will later claim a delta against. Response speed and no-show are forward standards, not measured befores. Words only.
  • Never compute conversion. Showing-completed and offer-made stay blank — class C, the client’s to measure, never ours.
  • Conservatise M_w ~20%. The per-task “yes” is what locks it and makes the number theirs, not flattering.
